# Data Model: Persistencia Local SQLite de Tarefas

## Task

Represents the same task entity defined by the TODO API, now stored durably in SQLite.

| Domain Field | Storage Column | Type | Required | Rules |
|--------------|----------------|------|----------|-------|
| `id` | `id` | text | yes | UUID v4 generated by the application; primary key |
| `title` | `title` | text | yes | Trimmed by domain rules; non-empty |
| `description` | `description` | text | no | Optional; null/absent means no description |
| `priority` | `priority` | integer | no | `1` = high, `2` = medium, `3` = low |
| `status` | `status` | text | yes | `pending` or `completed` |
| `createdAt` | `created_at` | text | yes | Stable serialized date-time from creation |
| `updatedAt` | `updated_at` | text | yes | Stable serialized date-time from latest change |

## Relationships

No new entity relationship is introduced. The feature stores a single task collection in
one local SQLite database file.

## State Transitions

```text
create
  |
  v
pending -- complete --> completed
```

- Completing an already completed task remains idempotent.
- Updating title, description or priority does not change status.
- Deleting a task removes it durably and it must not reappear after restart.
- Reopening a completed task remains out of scope.

## Repository Port

The existing `TaskRepository` contract remains the boundary used by application use cases:

```text
create(task)
findAll()
findById(id)
save(task)
delete(id)
```

The SQLite adapter maps rows to domain `Task` instances and maps domain tasks back to
rows. Controllers HTTP and use cases do not receive Knex, SQLite connections or queries.

## Persistence Rules

- The SQLite file may be absent before first startup.
- Migrations must create the schema before the application serves any request.
- Failed migrations must fail startup in a controlled way.
- Reads and writes must preserve all existing task attributes.
- Storage failures must be translated to standardized application errors without exposing
  sensitive environment details.
